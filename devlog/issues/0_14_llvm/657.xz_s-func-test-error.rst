作者:zwx1144326(周兵)

问题描述
========
657.xz_s跑完后和specint改子项的预期输出进行比较出现问题:输出多了一行

========
预期的输出::

    SPEC CPU XZ driver: input=cpu2006docs.tar.xz insize=6643
    Loading Input Data
    Compressed size: 1287176; Uncompressed size: 9041920
    SHA-512 of decompressed data compared successfully!

    Finished compressing data
    Uncompressing previously compressed data
    Uncompressed data 6965690368 bytes in length
    Uncompressed data compared correctly
    Tested 6643 MiB buffer: OK!
    
实际的输出::

    SPEC CPU XZ driver: input=/remote/lms04/zwx1144326/BlockISA/PM_Cases/tm-spec17/657.xz_s/src/cpu2006docs.tar.xz insize=6643
    Loading Input Data

    Finished compressing data
    Uncompressing previously compressed data
    Uncompressed data 6965690368 bytes in length

使用标准比较命令比较之后,发现输出不对,使用软件比对发现,实际的输出多了"Compressed data 1036078272 bytes in length" 这一行
找对源码位置::

    fprintf(stderr, "Compressed data %" PRId64 " bytes in length\n", spec_fd[1].len);

发现这一行的输出是标准错误输出,意识到问题,是自己重定向使用失误
标准的执行::

    ./elf_file >> out.log 2>> err.log

自己的输出::

    ./elf_file $> out.log

结论
====
是自己的操作失误,未区分标准输出和标准错误输出,导致比较出错,实际该子项运行是正确的;

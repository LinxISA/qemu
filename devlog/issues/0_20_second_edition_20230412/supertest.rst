supertest 测例分析
*******************

介绍
=====

本篇主要是记录 supertest 用 QEMU 运行时产生的错误，以供后来者了解情况。

记录人：杨继钦 30042171

20230417
========

确认一下04/17版本supertest的问题，目前用clang编译出来的supertest执行上总共有三类问题:

1. 段错误，这个需要细看，一般是访问地址非法
2. abort，这个也需要确认一下

报错中只有一个abort错误，其余都是段错误，首先来确认一下abort问题，看看是什么原因
导致的。

首先仔细看看报错：

terminate called after throwing an instance of 'char const*'
Aborted

看起来是异常处理相关的代码产生的，按理来说，llvm出现这类问题是已经屏蔽的，因为目前
还不支持这类测例，去看看这个测例的源码，发现果然有异常处理相关代码，所以挂掉是符合
预期的，但是之前为什么没有挂？

去看看fail_list，没发现有这个文件，去跑一下0413提供的supertest测例，发现竟然通过了，
那么可以打开反汇编看看，发现之前这里的代码没把异常处理部分编译进去，一个简单的main
函数里基本什么都没有，就return了，所以可以测试通过，所以之前的测例通过应该算是偶然
现象，也没有验证异常处理的功能。所以这个测例我的理解是暂时可以加到fail_list里面。

跟王鑫确认了一下，这个问题先忽略，等待异常处理的实现。

接下来看看段错误的问题。

首先看到错误的指令::

   ...
   107d8:       0739                    ld      [sp,56]
   107da:       0067                    set     t#1,ra
   107dc:       e001                    addi    t#8,0
   107de:       e001                    addi    t#8,0
   107e0:       e001                    addi    t#8,0
   107e2:       e001                    addi    t#8,0
   107e4:       e001                    addi    t#8,0
   107e6:       e001                    addi    t#8,0
   107e8:       e080                    add     a6,ra
   107ea:       401b                    sh      t#3,[t#1,0]
   ...

出错的地方是一条sh指令，报段错误，那么就可以确认是访问的地址有问题，首先看看这个
地址怎么来，访存地址是a6和ra相加的结果。

先看看这两个分别是什么值，可以加-cpu,看看add的结果，还有a6和ra的数据来源是否正确，
发现访存地址是220f0，这个地址之前还没有见过，然后a6和ra分别是11088和11068，相加的确
为220f0，那么看看a6和ra从哪里来。

往上看，可以看到107da这个pc，从 sp + 56的内存地址里取数，然后写进了ra里面，通过-cpu的
打印，可以看到取出的数就是11068，再往上可以看到a6是直接从gpr获得的，一条get a6指令，
也就是说两个数的源头还没找到，不在这个块中。

一路往上，看到这两个数之前就存在栈里面了，分别存在 sp + 216和sp + 208中，所以找找
初始化的地方，应该就能找到这两个是什么数了。

可以看到1033e这个pc值，这里用一条lwu.ip，从数据段中取出来11068，也就是这应该跟变量
有关，去看了相应的数据段，的确为11068，然后写进了sp+208中，然后1031e这个pc，也是
一条lwu.ip指令，从数据段中读出来11088这个值写进sp+216中，执行过程都没有问题。

那么看看11068和11088分别代表了什么，用readelf打开可执行文件，发现它们是d_uch和d_ush两
个数组的地址。那么这里的汇编就是两个数组地址相加，然后往里面写数。

按照道理来说，c不会这么写，不符合逻辑，一版是往数组里面写数，可以用地址加上偏移，
但是数组地址加数组地址这种操作，显然有点不合理。

发现0404这个测例是能够通过的，看了一下反汇编，发现相同的地方，写数据的地址变成了
11088 + 28，也就是一个数组地址加上偏移，那么明显两者的汇编就不等价了。

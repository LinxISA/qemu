500.perlbench_r测例分析
*************************

介绍
======
500.perlbench_r 子项在用LLVM-v0.20第二版优化版本编译器编译后，在qemu上运行出现
段错误的问题。

本篇就是用来记录 500.perlbench_r 问题分析。

分析
======
1、首先通过gdb调试qemu运行464测例的程序::
    
    gdb --args ./qemu-linx -d in_asm,out_asm,exec -D qemu.log
    
跑到段错误的位置，然后打印下 p/x $pc, 看host的pc；根据这个pc在qemu日志中找对
应的blockisa编译后程序内bpc或tpc::

    p/x $pc

找到这里，梳理下反汇编逻辑，s3 中存的是 buf 内数据求或以后的结果::

    反汇编逻辑：
    t#1 ( t#1(t#1([a4 + 25] << 8) or t#2([a4 +24])) or t#2([a4 + 26] << 16)) 
        or t#7([a4 + 27] << 24)
    源码：
    ((tmp) = (U32)(*buf) | ((U32)(*(buf+1)) << 8) | ((U32)(*(buf+2)) << 16) 
        | ((U32)(*(buf+3)) << 24))

在此可以看出，在 BPC 为 296a10 的块内微指令， a4 中存放的是此运算后的数值，而在
段错误发生的 lbu 指令，应当加载的数值当作地址用，导致发生的段错误。

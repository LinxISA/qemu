600.mcf子项切片段错误问题分析
*******************************

问题描述：
==========
0.13llvm编译器生成的切片，出现了段错误的问题；

分析：
======
查看了源码和对应的汇编代码，发现了两者逻辑不一致的现象。

先看c代码，出错函数是Perl_safesyscalloc这个地方

.. code-block:: c

    void *
    Perl_safesyscalloc(size_t count, size_t size)
    {
        void * ptr;
        if (size && (count <= ((size_t)~0) / size)) {
        }
        else {
            S_croak_memory_wrap();
        }
        if (count && size)
            ptr = (void *)calloc((count), (size));
        else
            ptr = (void *)calloc((count ? count : 1), (size ? size : 1));

        (void)0;
        if (ptr != ((void *)0)) {
     return ptr;
        }
        else {

     extern int Perl___notused(void);

     if (PL_nomemok)
         return ((void *)0);
     Perl_croak_no_mem();
        }

        return 0;
    }

只看第一个 if语句先，后面的忽略，调用函数的在count为1，size为4072的情况下，函数会
进入if语句，什么都不做，不会进行S_croak_memory_wrap()的函数调用。

0x61a540是S_croak_memory_wrap()这个函数调用，所以理解一下这个汇编代码，可以理解为这样
的一段c代码：

.. code-block:: c

    if (size == 0) {
        int x = 40042632;
        int y = 9827090;
        S_croak_memory_wrap();
    }
    else {
        if(size * count == 0){
            if((count >= 1 && size >=1) == 0){
                S_croak_memory_wrap();
            }
            else{
                 ...//忽略，当前条件走不到
            }
        }
        else{
        int x = 40042632;
        int y = 9827090;
        S_croak_memory_wrap();
        }
    }
  
然后，在count为1，size为4072的情况下，这段函数就不对等，走到了最后一个else，调用
S_croak_memory_wrap()；引发了循环调用的问题。

造成这样编译器出来汇编代码跟原本c代码逻辑不对等的情况，编译器的王涛确认了，这是
mulhu指令缺少而导致的问题，当前的版本无法解决，等编译器的版本更新.

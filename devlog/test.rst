Linx测试方案
***********************

1. 目标
=======

本文的写作目的是制作一个测试计划，在qemu-linx上面完成单条指令的添加后，通过组合
测试和边界条件测试，验证实现中是否有其他漏洞。

2. 策略
=======

为了实现qemu-linx的开发目标，要用以下策略保证目标完成:

1. 定义清楚编码指令的语义，用例子说明，避免理解不一致，例如sub指令中link1和link0
   的实际使用含义和使用次序（减数和被减数）。保证测试结果和指令行为定义相同。
2. 更多的组合进行测试。例如：add、sub、mul、div组合运行。在一个测试用例中单独块
   中组合多条指令或是在一个测试用例中组合多个块运行以及进行多个分支跳转测试。
3. 单独指令的边界测试。例如：add、sub、mul、div等溢出，跳转的边界溢出等情况。
4. 所有的测试编译成一个可执行程序。测试结果显示 pass 或者 failed。

3. 详细定义
===========

1. 用例：两个const拼接，第一个const的数是高位，第二个const的数是低位，第二个
   const要用新的T寄存器下标::

    CONST c=1 imm1=imm ->T0
    CONST c=0 imm2=imm  /* imm1<<7 | imm2 ->T1 */

2. 两个操作数的关系：link0 op link1 ，例如sub/div等

3. 用例:SET等没有目标寄存器的指令，也占用一个T寄存器下标。每条指令使用的link的
   偏移定义是：相对自己的指令地址的指令的输出。::

	GET  ->T0
	GET  ->T1
	ADD  ->T2
	SUB  ->T3
	SET  ->T4   #注意这里SET不占用T寄存器，但依旧占用T寄存器下标
	ADD  ->T5

4. 溢出由上层应用自己判断，tcg不报异常

5. div/rem等除数异常。RV是底层进行除数为0的比较，避免coredump。这里linx采用类似
   思路。一个数除以0等于-1，一个数除以0余数是本身。

4. 边界测试
===========

边界测试指的从长期的测试工作经验得知，大量的错误是发生在输入或输出范围的边界上，
而不是在输入范围的内部。因此针对各种边界情况设计测试用例，可以查出更多的错误。使
用边界分析方法设计测试用例，首先应确定边界情况。通常输入等价类与输出等价类的边界，
就是应着重测试的边界情况。应当选取正好等于，刚刚大于，或刚刚小于边界的值做为测试
数据，而不是选取等价类中的典型值或任意值做为测试数据。

5. 综合测试用例
===============

目的：测试块边界处理有没有问题

测试策略：定义三个算法，用RV算n个加法；用linx计算n个块计算n个加法；用linx一个块
算n个加法。

目的：测试跨页内存溢出是否正常

测试策略：分配两个连续的页，madvice让第二个页失效，在一个block中设计两条指令，
一条访问第一个页，一个访问第二个页

目的：测试加减乘除的溢出是否正确

测试策略：给定两个数，加时一定会溢出，看结果是否正确。给定两个数，减时一定溢出，
看结果是否正确。给定两个数，乘时一定溢出，看计算结果是否正确。给定两个数，除时
一定溢出，看计算结果是否正确。

目的：加减乘除的混合运算验证

测试策略：在一个块中同时调用多个加减乘除的运算，对比结果是否正确。

目的：函数的多层调用

测试策略：
方法1：递归调用，看调用多次结果是否正确。
方法2：不同函数调用，多层调用，看结果是否正确。

目的：测试函数传递参数的边界值

测试策略：函数调用传递参数验证例如16个，要超过8，T寄存器的个数是8.

目的：访问T寄存器的边界

测试策略：T寄存器限制8个，函数内部变量超过8个时，报错提醒。

目的：测试内存修改的边界

测试策略：内存修改不超过32个时，正常。当超过32个时报错。

目的：测试多分支跳转是否正常

测试策略：写一个函数，内部根据数值比较是否相等，若相等跳转，若不等则不跳转。给
定不同的输入得到不同的结果。

目的：测试分支跳转的距离边界

测试策略：128以内的跳转，128以上通过liac实现跳转。共享库的调用，测试边界。
